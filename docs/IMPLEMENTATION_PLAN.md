# LOB Document 实施计划

## 1. 目标与边界

LOB Document 研究非结构化文件如何转换为可被检索、生成和审计系统消费的结构化数据。首期聚焦 PDF，同时建立可扩展到 Word、Markdown 和图片的统一协议。

完整链路必须回答：输入文件如何识别，页面中有哪些内容，阅读顺序如何恢复，OCR 与原生文本如何去重，表格和公式如何表示，输出如何定位回原文，以及解析质量如何量化。

## 2. 核心领域模型

```text
SourceDocument
  ├─ FileIdentity / Metadata
  ├─ Page
  │   ├─ BoundingBox
  │   ├─ TextBlock / Heading / Paragraph / List
  │   ├─ Table / Cell
  │   ├─ Figure / Caption
  │   ├─ Formula
  │   └─ Diagnostic
  ├─ DocumentTree
  ├─ RagChunk / SourceRef
  └─ QualityReport
```

所有内容节点至少携带稳定 ID、页码、坐标、类型、阅读顺序、来源方式和置信度。解析告警属于一等数据，不能只写日志。

## 3. 分阶段实现

### 阶段 0：研究基线、样例集与统一领域模型

步骤：

1. 固定 MinerU、Docling、MarkItDown 的版本、许可证和源码提交。
2. 建立原生 PDF、扫描 PDF、双栏、跨页表格、公式、图片和异常文件样例集。
3. 定义 `SourceDocument`、`Page`、`Block`、`BoundingBox`、`SourceRef` 和 `Diagnostic`。
4. 定义坐标系、节点 ID、阅读顺序、置信度和错误分类。
5. 提供 CLI 骨架及 JSON Schema 输出。

验收：同一输入可生成稳定文件身份和空文档结构；协议能够表达后续所有固定样例。

### 阶段 1：原生 PDF 文本、坐标与页面结构

步骤：

1. 解析 PDF 元数据、页尺寸、旋转方向和加密状态。
2. 提取字符、文本行、字体、字号和坐标。
3. 将字符聚合为行和初级文本块。
4. 识别并移除重复文本层与不可见字符。
5. 输出逐页 JSON 和可视化坐标调试产物。

验收：固定原生 PDF 的正文无明显丢字；每个文本块可准确映射到页码和区域。

### 阶段 2：版面分析、阅读顺序与文档树

步骤：

1. 分类标题、正文、列表、页眉、页脚、脚注和侧栏。
2. 处理单栏、双栏和混合版面阅读顺序。
3. 合并行内片段、段落和跨页连续内容。
4. 根据编号、字体和空间关系恢复标题层级。
5. 生成可遍历的 `DocumentTree`。

验收：固定双栏文档的 Markdown 顺序正确；页眉页脚不会混入正文；标题层级可重复生成。

### 阶段 3：扫描件 OCR 与原生文本融合

步骤：

1. 判断页面是否需要 OCR，避免无条件重复识别。
2. 渲染页面并执行 OCR，保留文本框和置信度。
3. 统一 OCR 坐标与 PDF 页面坐标。
4. 合并 OCR 与原生文本，处理重复、冲突和缺失。
5. 记录低置信区域、语言和旋转校正诊断。

验收：扫描样例可生成可读正文；混合型 PDF 不出现大面积重复文本；低置信内容可追踪。

### 阶段 4：表格、图片和数学公式

步骤：

1. 定位表格区域，恢复行、列、单元格和合并关系。
2. 处理无框线表格、跨页表格与重复表头。
3. 提取图片、图注、页面位置和内容哈希。
4. 检测行内与块级公式，保留原图和可用表示。
5. 为复杂内容设计 Markdown 降级规则和结构化 JSON。

验收：表格结构可按单元格核对；图片与图注关联；无法可靠识别的内容明确降级而非静默丢失。

### 阶段 5：多格式 Loader 与统一输出

步骤：

1. 增加 Word、Markdown 和图片 Loader。
2. 将格式特有对象归一化到统一文档模型。
3. 输出 Markdown、JSON 和纯文本。
4. 保存原始元数据、附件关系和转换诊断。
5. 保证相同语义在不同 Loader 下使用一致节点类型。

验收：四类输入都通过同一 CLI 和服务接口解析；下游无需按文件类型编写分支。

### 阶段 6：RAG Chunk、引用溯源与 lob-vector 集成

步骤：

1. 基于文档树按标题、段落、表格和 Token 预算分块。
2. 保留 Chunk 到节点、页码、坐标和原文件的映射。
3. 避免将标题、表格和跨页语义任意截断。
4. 定义解析结果版本和增量更新身份。
5. 接入 `lob-vector` 导入协议并验证引用回跳。

验收：检索结果可定位到原文件具体页面和区域；重复导入不会生成不可控重复数据。

### 阶段 7：质量评测、批处理与生产化

步骤：

1. 建立文本覆盖率、阅读顺序、结构准确率和表格相似度指标。
2. 对 MinerU、Docling、MarkItDown 和自研链路运行固定样例对比。
3. 记录单页耗时、吞吐、内存、失败率和降级次数。
4. 实现批处理、取消、超时、重试和资源配额。
5. 增加文件大小、页数、解压炸弹和恶意输入边界。
6. 提供解析任务、产物和诊断查询 API。

验收：每次版本变更可运行固定回归；失败能定位到 Loader、页面或处理阶段。

### 阶段 8：源码映射与差异清单

步骤：

1. 追踪 MinerU 从文件输入到中间模型和最终输出的调用链。
2. 映射 Docling 的格式后端、转换管线、文档模型和序列化入口。
3. 映射 MarkItDown 的格式分发、转换器和 Markdown 输出入口。
4. 形成“参考源码对象 → LOB Document 对象 → 差异与原因”清单。
5. 记录未实现能力、模型依赖、许可证约束和生产风险。

验收：至少完成 PDF 原生文本、OCR、版面恢复、表格和输出五条调用链映射。

## 4. 推荐目录

```text
src/lob_document/
  domain/       文档、页面、节点、来源和诊断协议
  loaders/      PDF、Word、Markdown、图片载入
  layout/       布局分类、阅读顺序和文档树
  ocr/          OCR 适配、坐标归一和文本融合
  tables/       表格检测与结构恢复
  formulas/     公式检测、识别和降级
  exporters/    Markdown、JSON、文本和可视化输出
  chunking/     面向 RAG 的结构化分块与引用
  evaluation/   样例集、判定器、指标和对比实验
  api/          CLI、任务服务和查询接口
```

依赖方向保持单向：入口负责编排，领域模型不依赖解析 SDK，各类解析器通过接口接入。

## 5. 每阶段执行节奏

1. 固定输入样例和预期结构。
2. 定位参考项目源码入口与完整调用链。
3. 更新源码映射和差异说明。
4. 实现最小纵向闭环。
5. 运行只覆盖当前能力的定向验证。
6. 保存失败样例、质量指标和下一步判断。

## 6. 统一完成标准

- 原始文件、结构化节点、Markdown 和 RAG Chunk 可以双向追溯。
- 内容丢失、顺序不确定和低置信识别必须产生结构化诊断。
- 固定样例输出稳定，关键质量指标可重复计算。
- 不因追求统一格式而静默丢弃表格、公式、图片或版面信息。
- 每项实现记录参考源码入口、刻意简化点和适用边界。
