# LOB Document 演示版实施计划

## 1. 当前目标

实现一个可演示的文档解析 MVP：通过本地 Web 工作台或统一 CLI 输入 PDF、Word、Markdown 或图片，生成结构化 JSON、可阅读的 Markdown 和图片资产，展示文本提取、OCR、基础结构与来源信息。演示闭环为“上传文件 → 解析 → 原文对照与结果预览 → 下载”。

本期交付是可重复运行的解析演示，不是完整 RAG 平台或生产级服务。此前阶段 0～8 的路线调整为“本期演示范围 + 后续可选扩展”，不再要求全部阶段完成后才可交付。

## 2. 本期范围与状态

- 已实现统一文档模型、稳定 ID、JSON Schema 与 CLI。
- 已实现原生 PDF 文本、页码、坐标、字体信息和基础版面提取。
- 已实现基础阅读顺序、标题层级、页眉页脚处理与文档树。
- 已实现本地 Tesseract、SiliconFlow 云端 OCR 和原生文本融合。
- 已实现基础表格恢复与导出、图片提取和图注关联。
- 已实现 PDF、Word、Markdown、图片 Loader，以及 JSON/Markdown 统一输出。
- 已实现 React 工作台与本地 FastAPI 服务，支持上传、OCR 设置、任务状态、结果预览、诊断查看和下载；`./start.sh` 一键启动。
- 已有来源引用和结构化诊断：PDF/图片使用页码与坐标，Word/Markdown 使用顺序或行号语义；不等同于 RAG 回跳或完整质量报告。
- 待完成演示样例选择、运行环境确认与逐项输出验收。

“已实现”描述现有代码能力，不承诺任意文档都能准确解析，也不因目标调整而自动视为验收通过。

## 3. 演示收尾步骤

1. 选定可本地使用的原生 PDF、扫描 PDF、Word、Markdown、图片各一份；整体覆盖标题、正文、基础表格和图片，不要求每份样例包含全部元素。
2. 确认 Python 3.12+、`uv` 和项目依赖可用。OCR 选择一种可用路径：本地 Tesseract 及对应语言包，或配置 SiliconFlow 并显式允许云端处理。
3. 用统一 `parse` 命令逐份生成 JSON、Markdown 和适用的图片资产。原始文件只读，产物写入独立 `artifacts/` 目录。
4. 对照输入核对正文、基础阅读顺序、表格、图片及来源字段；检查诊断，记录样例的缺失或降级情况。
5. 保留演示命令、样例说明和已知限制，确保可以重复操作。只做针对样例的最小必要检查，不为本期新增评测平台或测试依赖。

命令模板（将占位路径替换为实际样例）：

```bash
uv run lob-document --help
uv run lob-document parse <样例路径> --output artifacts/demo/result.json --markdown artifacts/demo/result.md
uv run lob-document schema --output artifacts/demo/source-document.schema.json
```

每份样例使用独立输出路径，避免覆盖其他演示结果。无需 OCR 的样例可添加 `--ocr never`；扫描 PDF 和图片需要可用 OCR。云端演示添加 `--ocr-engine siliconflow --allow-cloud-ocr`，密钥仅通过本地环境配置，不写入文档或演示产物。

## 4. 本期完成标准

- [ ] `./start.sh` 可启动工作台，网页可上传文件、查看真实解析状态与失败原因。
- [ ] 可在页面对照原文查看阅读预览、Markdown、JSON 与诊断；Word 原文件以下载方式提供。
- [ ] Markdown、JSON 与 ZIP 结果包可下载，云端 OCR 必须明确授权。
- [ ] 五类固定样例均可通过同一 CLI 运行，生成可打开的 JSON 和 Markdown。
- [ ] 原生 PDF 样例主要正文可读，基础顺序和标题结构符合演示预期。
- [ ] 扫描 PDF 和图片样例在选定 OCR 环境下能输出可读文字。
- [ ] 选定样例的基础表格和图片可以在输出中查看，相关资产路径可用。
- [ ] 可从 JSON 或 Markdown 的来源信息核对到输入位置；不要求交互式回跳界面。
- [ ] 同一输入重复运行时文件身份稳定，相同解析内容的节点身份稳定；不要求云端 OCR 内容逐字一致。
- [ ] 已核对现有诊断并记录已知限制，不把内容缺失误报为完整解析。
- [ ] 已保存样例说明和运行命令，能够按说明重复演示。

以上通过即可判定本期目标完成。当前核心能力已有实现，剩余工作是演示收尾和输出核对，不要求实现以下扩展项。

## 5. 后续可选扩展（不计入本期验收）

- 复杂双栏与混合版面、跨页段落、脚注和侧栏的精细恢复。
- 无框线表格、跨页表格与重复表头的可靠处理。
- 行内及块级公式识别、原图保留和可靠降级。
- 纯文本导出、更多输入格式与附件关系。
- RAG Chunk、Token 预算、增量身份、`lob-vector` 导入与检索引用回跳。
- 文本覆盖率、阅读顺序、表格相似度等系统化评测与工具对比。
- 批处理、取消、超时重试、资源配额、恶意输入防护和任务查询 API。
- MinerU、Docling、MarkItDown 的版本基线、源码调用链映射与差异研究。

## 6. 保留的工程边界

- 核心领域模型不依赖具体 PDF、OCR 或模型 SDK，解析能力通过独立模块接入。
- 不绕过加密、访问控制或文档权限。
- 未经显式允许，不向云端发送页面数据。
- 不训练 OCR、布局或视觉模型，不承诺生产级吞吐、可用性或任意文档准确率。
- 现有诊断作为结果的一部分保留，演示中明确解释已知限制。

## 7. 当前实现验证（2026-09-04）

- 前端 TypeScript 检查与生产构建通过，启动脚本语法检查通过，工作台首页返回 HTTP 200。
- 使用内存生成的小型原生 PDF、Word、Markdown 和图片验证真实上传、解析、原文件读取与 ZIP 下载；图片资产接口可访问。
- 英文扫描 PDF 的本地 OCR 验证通过；无文字图片块进入文档树与 Markdown，修复了原有的漏图问题。
- 空文件、不支持的格式、损坏 DOCX、未授权云端 OCR 和跨站提交被拒绝；损坏 PDF 产生失败任务。
- 服务重启后已完成记录仍可查询；Markdown 安全过滤移除脚本与事件属性，同时保留合并单元格结构。
- 未进行浏览器逐项交互验收或云端 OCR 调用；本机没有 `chi_sim` 语言包，中文扫描件仍需安装语言包或显式授权云端识别。
- 页面提供可选的 WebMCP 当前结果只读入口；未在支持该能力的浏览器上下文中验证，不影响普通网页操作。
